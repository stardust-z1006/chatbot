# deepChat v1 · 使用说明

项目结构、装依赖、跑起来的第一分钟看根目录 `README.md`；本文只管「怎么用」。

## 怎么用

```
双击 start.bat    出菜单：启动 / 发送自检 / 环境自检 / 建索引 / 开面板
                  （直接回车 = 启动机器人，窗口别关，后台面板跟着起）
```

命令行（在项目根目录下）：

```
.venv\Scripts\python.exe run.py                 # 同菜单
.venv\Scripts\python.exe run.py run             # 直接启动机器人
.venv\Scripts\python.exe run.py selftest        # 发送自检（真发一条到文件传输助手）
.venv\Scripts\python.exe run.py doctor          # 环境自检
.venv\Scripts\python.exe run.py ask 推荐个咖啡   # 不接微信，直接测整条链路
.venv\Scripts\python.exe run.py index           # 增量建索引（--force 全量）
.venv\Scripts\python.exe run.py web             # 只开后台面板，不接微信
```

回归测试在 `tests\`（改了核心代码就跑一遍）。十个脚本互相独立，全部跑完约 50 秒：

```
.venv\Scripts\python.exe tests\run_all.py           # 全跑，末尾给一张汇总表
.venv\Scripts\python.exe tests\run_all.py memory    # 只跑名字含 memory 的那个
```

单个脚本也能直接跑，看得到每条断言的中间过程：

| 脚本 | 验什么 |
|---|---|
| `test_context_budget.py` | 闸门预算回砍、回复切分、重复消息 |
| `test_memory.py` | 记忆写入、检索门槛、查重合并、容量淘汰 |
| `test_identity_isolation.py` | 别人的记忆一条都捞不到 |
| `test_concurrency.py` | 并发：同会话串行、跨会话并行、指纹恰好一次 |
| `test_tool_loop.py` | 工具循环：正常 / 预算截断 / 轮次用尽 / 坏输入 |
| `test_group_engage.py` | 群聊接话打分：被叫到就回、不插嘴 |
| `test_group_log.py` | 关键用户群消息记录（只追加流水） |
| `test_panel.py` | 后台面板：接口、改参数、恢复默认、重建索引 |
| `test_send_guard.py` | 发送护栏：同一条回复不会被发两遍 |
| `test_integration.py` | 端到端：真 Bot + 假微信 + 假模型 |

## 工具（模型自己决定用不用）

| 工具 | 做什么 | 什么时候用 |
|---|---|---|
| `now` | 报当前时间 | 算「今天/明天/最近」之前先对表 |
| `web_search` / `read_url` | 联网搜索、读网页正文 | 需要最新信息、或者对方发来链接 |
| `weather` | 中国天气网实况 + 预报 | 问天气 |
| `kb_search` | 查 `knowledge\` 里的资料 | 问「我的资料里写过的」细节 |
| `chat_history` | 翻微信聊天记录（只读） | 「上次那个」「我们聊过」 |
| `remember` | 主动记一条事实 | 明显值得长期记住的信息 |
| `speak` | 排一条语音（mp3 文件） | 撒娇、道晚安；`voice.enabled` 关着就没有 |

一次回复最多 `llm.tool_rounds` 轮（默认 4），工具结果累计吃 `llm.tool_budget`
（默认 6000 token），超了当场截断并注明「已截断」。轮次用完还在调工具时，
会不带工具再问一次，逼它出正文。任何工具失败都只回一句说明，不会中断回复。

## 后台面板

地址 `http://127.0.0.1:8787`，跑 `run.py open` 直接开。
面板跟机器人**同一个进程**（`start.bat` 跑起来时顺带起），
所以看到的是真实运行数据，改参数也是直接改内存里那份 `Settings`。

版式是左边一列分区、右边一块白面板，地址栏带分区名（`#memory` 这种），
刷新页面不会跳回总览。

### 十四个分区

| 分区 | 里面有什么 |
|---|---|
| 总览 | 8 张数字卡（消息/平均耗时/上下文占用/记忆/资料库/工具调用/失败/运行时长）、最近 40 条消息、每个工具的调用次数与平均耗时 |
| 角色库 | 左边一列角色、右边编辑正文。可新建 / 改名 / 删除 / 设为默认。保存后**下一句就用新人设** |
| 会话监视 | 每个群、每个人单独设：正常回复 / 只在 @ 时回 / 只看不回 / 完全不看；可以**指定角色**；群里还能**只理某些人 / 不理某些人** |
| 用户等级 | 默认等级、主人的 wxid、机器人别名、接话打分的开关与三个分数线（7 项）＋ **已设等级的人**列表：改等级 / 设称呼 / 删除 |
| 对话与发送 | 合并窗口、只回最近多久、群里 @ 规则与关键词、私聊默认回不回、气泡字数/条数、打字间隔、冷却、轮询间隔、监听清单（12 项） |
| 模型与工具 | 模型名、温度、单次上限、超时、重试、工具轮次与预算（7 项） |
| 记忆 | 容量/门槛/权重（6 项）＋ **记忆库浏览**：最近的记忆、类型、重要度、用过几次、写入时间，可以作废；还有一个语义检索测试框（不写库、不算使用次数） |
| 联网 | 搜索条数、抓几篇正文、截取字数、超时（5 项） |
| 资料库 | 开关、取几段、扫描目录、文件类型（4 项）＋ **已索引文档表**（标题/路径/字数/分块/更新时间）＋ 重建索引按钮 |
| 聊天记录 | 开关、默认往回翻几天（2 项） |
| 语音 | 开关、模式、音色、语速、音调、长度限制（8 项）＋ **试听**：写一句话用当前音色合成，页面上直接播 |
| 工具清单 | 按当前配置真正挂上的工具：名字、给模型看的说明、参数、本进程调用次数 |
| 日志 | 最近 200 条，按级别染色；可按关键词/级别过滤，可暂停、可自动滚到底 |
| 系统 | 路径、Python 与依赖版本、进程号、面板地址；面板端口开关；记忆快照/清空面板记录；**被覆盖的参数一览** |

### 多个角色，各聊各的

角色就是 `prompts/personas/` 下的一个 md，文件名即角色名。
「默认角色」给没单独指定的会话用；想让某个群换性格，去「会话监视」给它绑一个角色。

```
prompts/personas/
├── deep.md        默认角色（原来那个 persona.md 会自动搬过来）
├── 损友.md        给损友群绑这个
└── 客服.md        给客户私聊绑这个
```

`data/personas.json` 只记「默认是哪个」，绑定关系在 `data/chats.json` 里——
绑定的唯一事实来源只有一处，不会出现「改了面板另一边没变」。

### 会话监视：谁值得回、谁只看不回

| 模式 | 行为 | 典型场景 |
|---|---|---|
| 正常回复 | 进来什么就回什么 | 私聊、朋友的群 |
| 只在 @ 时回 | 要 @ 或命中群关键词才回 | 大群、工作群 |
| 只看不回 | 收下来但不回、也不记 | 只想看、不想插嘴的群 |
| 完全不看 | 连日志都不记 | 不想让机器人碰到的地方 |

没单独设过的会话按 config 的默认值走（`group_at_only` / `reply_private`）。
所有改动**下一条消息就生效**，不用重启。

### 群里再挑人：只理谁 / 不理谁

「会话监视」表格里有一列**成员**，点开是这个会话里最近说过话的人（带发言条数）：

- **所有人都算**（默认）
- **只理这些人**：勾上的人说话才算数，其他人当没看见
- **不理这些人**：勾上的人一律不理，其他人照常

名单同时认**昵称和 wxid**——显示的是昵称好认，但昵称会改、也可能重名，所以 wxid 也匹配。
不在最近消息里但想加的人，直接在上面输入框敲名字回车加进去。

两个细节：
- 规则判断在「去重」和「合并」之前，被拦掉的消息不会留下指纹
- **只理 + 空名单 = 所有人都算**（`ChatPrefs.allow_sender` 里空名单直接短路放行）。
  这条是刻意的：空名单按「只理」理解会把整个群关死，那属于配置事故而不是功能。
  面板另外拦了一道，不让「只理 + 一个人都没勾」保存出去

### 关键用户：谁在群里说的话会被记下来

群里的消息默认**不进记忆库**（隐私 + 名额），但「我在群里说过什么」有时需要能查。
所以单独有一份**流水**：只记关键用户，只追加，不参与检索、不影响回不回。

**谁算关键用户**（三级判定，只看第一条命中的）：

| 序 | 规则 | 怎么设 |
|---|---|---|
| 1 | `data/people.json` 里有明确记录 | 面板/接口设等级，见下 |
| 2 | 命中 `config.yaml` 的 `people.owners` | 填 wxid 或昵称，按**主人**算 |
| 3 | 命中 `config.yaml` 的 `group.key_users` | 填 wxid 或昵称，按**熟人**算 |
| 4 | 都没命中 | 用 `people.default_level`（默认 `stranger`，不记） |

四个等级：`owner` 主人 / `friend` 熟人 / `stranger` 陌生人 / `blocked` 不理。
**只有 owner 和 friend 会被记录**；`blocked` 是「完全不处理」，连记录都不留。

设置入口三个（改完下一条消息就生效）：
- 面板「用户等级」分区：`已设等级的人` 列表里直接点等级 / 设称呼 / 删除；也可以填 `主人的 wxid`、`关键用户` 种子
- 改 `config.yaml` 的 `people.owners` / `group.key_users`
- 接口：`GET /api/people` 看现状，`POST /api/people` 传 `{"wxid":"wxid_xxx","level":"owner","alias":"老板"}`，`POST /api/people/forget` 删一条

**记哪些字段**（一条消息一行）：

| 字段 | 内容 |
|---|---|
| `op` | `msg`＝一句话，`reply`＝机器人的回复 |
| `ts` / `msg_time` | 记录时间 / 微信消息时间 |
| `chat_id` / `chat_name` | 群 wxid / 群名（记录时的快照，群改名不影响旧记录） |
| `sender` / `sender_name` | 说话人的 wxid / 显示名 |
| `level` / `alias` | 记录当时的等级 / 你给他设的称呼 |
| `msg_key` / `msg_type` | 消息指纹（去重用）/ 类型 |
| `text` | 正文，超过 500 字截断并标 `…` |
| `score` / `reasons` | 接话判定的得分与构成（见下面「群聊怎么判定回不回」） |
| `replied` / `reply` | 是否回复 / 回复正文前 200 字（`reply` 行里是 `ok` 发送结果 + `msg_keys` 关联） |

**存在哪**：`data/group_log/2026-10-26.jsonl`，一天一个文件，UTF-8，一行一个 JSON。
- 一行坏掉只跳过那一行，不影响其他行
- 文件名即日期，读最近 N 天不用扫全库
- 保留 `group.log_days` 天（默认 30），启动时删掉过期的日文件
- 关掉：`group.log_enabled: false`（面板「对话」分区也能关）

**什么时候记**：群聊 + 关键用户 + 不是噪音（≥2 字、含文字、不是撤回/入群提示）。
位置在**「完全不看」之后、「只看不回」之前、「@ 判定」之前**，三条都不能挪：
- `off` 的群连日志都不写，更不该留正文
- `silent`（只看不回）恰恰是最需要留痕的场景
- 判成「不回」的消息同样要留，否则没法事后算「到底漏在哪」

私聊不记（私聊本来就进记忆库，再记一遍是冗余）。

**用途**（按重要性）：
1. **回溯**：这条为什么回 / 为什么没回，`score`+`reasons`+`replied` 能还原
2. **调参**：这些记录就是一份带标注的数据集，能算准召，比拍脑袋调阈值靠谱
3. **导出**：`http://127.0.0.1:8787/api/group-log?limit=50`（可加 `&chat=` `&sender=`）
4. 将来群内记忆启用时，记忆条目上记一个 `msg_key` 指回这里，**不抄一份原文** ——
   同一条信息存两处，改一边另一边必然走样

### 群聊怎么判定回不回（接话打分）

默认群里是「at 模式」：不再只认 `@`，而是给每条群消息**打分**，过线才回。
这是「第一句被叫到、之后能接着聊」的核心 —— 被 @ 过一次之后，紧跟着的追问不用再 @。

**六个信号**（权重写死，面板不给调）：

| 信号 | 分值 | 例子 |
|---|---|---|
| 被 @ 且认得出是我 | +100 | `@deepChat 在吗` |
| @ 了一个「不在群里」的名字 | +60 | 排除法兜底：@ 陌生人多半在 @ 机器人 |
| 称呼命中 | +50 | `deep 在吗`（「DeepSeek」不会误中，做了词边界/呼语位置） |
| **连续性**：刚回过这个人 | **+40** | 回复成功后开 90 秒窗口，同一个人连说 3 轮延到 180 秒 |
| 疑问句 | +30 | 「那你觉得呢」 |
| @ 了群里的别人 | −50 | 别插嘴 |
| 太短（没人叫时） | −30 | 「哈哈哈」「👍👍」 |

**判定规则**：

- 被叫到（@ / 称呼）→ 分数 ≥ `call_score`（默认 50）就回，**叫名字永远叫得应**；
- 没被叫到 → 只有**主人**（≥ `join_owner`，默认 45）或**熟人**（≥ `join_friend`，默认 60）才会主动接话；
- **陌生人**永远只能被叫到，不主动接话。

**一个刻意的取舍**：冷启动不接话 —— 一段陌生对话的**第一句必须被叫到**，之后才靠连续性窗口。宁可少回一句，也不在别人的讨论里突然插嘴。

**开关**：`group.engage.enabled: false` 一键退回旧判定（只有 @ 或关键词才回）。判定结果在「总览」的 `engage` 计数和群记录里都能查（`score` / `reasons`）。

### 参数怎么改

共 **60 项**，按分区铺开，每项一行：人话名字 + 参数路径 + 输入框 + 单位 + 【保存】【默认】。
下面一行灰字写着「默认值 / 取值范围 / 为什么这么定」。

- 改完**下一条消息就生效**（面板会重建 Gate / Retriever / LLM / TTS）
- 标了「需重启」的才要重启：轮询间隔、监听清单、微信调试日志、面板端口/开关
- 改资料库目录或文件类型后，要再点一次「重建索引」
- 每个分区右上角有「本区恢复默认」，能一次回滚这一区改过的项
- 输入框正在打字时不会被 2 秒刷新冲掉

### 改的值存在哪

`data/override.yaml`，优先级高于 `config.yaml`，删掉这个文件就全部恢复默认。
`config.yaml` 一个字都不会被改——里面全是解释「为什么这么定」的注释，
程序回写一次就全没了，所以才单开一层覆盖。系统分区里能看到当前被覆盖了哪些项。

### 安全边界

只监听 `127.0.0.1`，没有登录。**别把 `monitor.host` 改成 `0.0.0.0`**：
这个面板能改配置、能改人设、能重建索引、能作废记忆，等同于这台电脑的使用权。

### 只开面板、不接微信

```
.venv\Scripts\python.exe run.py web
```

适合「先把参数调好再启动机器人」。此时顶部是灰色「未运行」，
记忆库/资料库/工具清单读不到真实数据（进程里没有 Bot），
改的参数照样落 `override.yaml`，重启机器人就按新值跑。

## 配置口径（`config.yaml`）

- `memory.capacity: 400` 满了淘汰最没用的（不降级）
- `memory.min_score: 0.55` 证据门槛，不到就不进上下文
- `memory.longterm: true` 关掉就不给模型 `remember` 工具（自动入库照旧）
- `wechat.max_age_minutes: 5` 只回 5 分钟内的消息（防止启动时补答昨晚的）
- `wechat.group_at_only: true` 群里只被 @ 才回（`group_keywords` 命中也算）
- `wechat.merge_window: 1.2` 连着发好几条时，攒够这么久再合并回一句
- `wechat.cooldown: 0.5` 两条消息之间至少隔这么久，防止连发抢焦点
- `llm.tool_rounds: 4` / `llm.tool_budget: 6000` 一次回复最多几轮工具、工具结果能吃多少 token
- `search.enabled` / `kb.enabled` / `history.enabled` / `voice.enabled` 四个能力总开关，
  关掉只是少一个工具，不影响聊天
- `voice.enabled: false` 默认关；`voice.mode: tool` 是「模型想发才发」，
  `always` 是每条都配一条语音（发的是 mp3 文件，微信 4.x 发不了语音气泡）
- `monitor.enabled / host / port` 后台面板开关与地址（默认 127.0.0.1:8787）
- `persona.dir: prompts/personas` 角色库目录，每个 md 一个角色
- `wechat.reply_private: true` 私聊默认回不回（单个会话可在面板里单独设）
- `people.owners: []` / `people.default_level: stranger` 谁按主人对待、没设过的人算哪一级
- `group.key_users: []` 谁算关键用户（群里说的话会被记进 `data/group_log`）
- `group.log_enabled: true` / `group.log_days: 30` 群记录开关与保留天数
- 面板改过的值落在 `data/override.yaml`，优先于 `config.yaml`

## 什么会进记忆，什么不会

规则在 `app/message_tagging.py` 的 `worth_remembering`，入库前唯一一道闸门：

| 类型 | 例子 | 结果 |
|---|---|---|
| 关于你自己的陈述 | 我在腾讯做后端 / 我只喝冰美式 | 存 |
| 待办、完结 | 记得明天提醒我交房租 / 那个已经搞定了 | 存 |
| 差遣她干活 | 帮我写个周报 / 推荐个咖啡 | 不存 |
| 提问、反问她 | 今天天气怎么样 / 我在哪家公司来着 | 不存 |
| 太短、系统提示 | 嗯 / 在吗 / xxx撤回了一条消息 | 不存 |

判据是「这句话在说谁」：主语是你自己就存；是在索取信息就丢。
中性陈述（「早餐吃了包子」）一律放过 —— 宁可存错也不能丢真的。

两条硬边界：

- **群聊完全不读写记忆。** 一是隐私（私聊说的私事被人 @ 一下就会当众复述），
  二是污染（群里的闲聊会占掉 400 个名额）。群里照样能聊，只是不记事。
- **这张疑问词表注定会被绕过。** 中文问法列举不完，例如「我在哪家公司上班」
  现在会存进去。它挡的是大部分噪音，剩下的靠容量淘汰兜底。
  真要彻底一点得让模型来判断，但那要给每条消息加一次调用，V1 不做。

## 踩过的坑（别再踩一遍）

1. **批处理必须 GBK + CRLF**，`chcp 65001` 之后不要写中文 echo。
2. **向量模型下载**要 `HF_HUB_DISABLE_SYMLINKS=1` + `HF_ENDPOINT=https://hf-mirror.com`，
   否则 Windows 上必报 `NO_SUCHFILE`。`app/embeddings.py` 里已写死。
3. **`deepseek-v4-flash` 会先思考再答**，`max_tokens` 太小会返回空字符串
   （4 个 token 直接空，256 才够）。`app/llm.py` 会自动放大重试。
4. **`.venv` 在项目根目录**，批处理里用 `.venv\Scripts\python.exe`。
5. **微信窗口被最小化 = 发不出去**（16:03 实测：UIA 敲不进输入框，消息静默丢）。
   发送前会自动还原窗口；面板总览和 `run.py doctor` 都会先报出来。
   这里**推翻**了之前「最小化也能发」的结论——那条是 12:14 单次实测的误判。
6. **先检索后写入。** 反过来的话这条消息会把「自己」检索出来（相似度 1.00），
   白占名额，看起来像「她记得你刚说的话」这种废话。
7. **别用长度猜信息量。** 「取更长的那条文本」在两个说法长度相近时直接失效。
8. **`帮我写周报` 里的「我」是宾语** —— 用「句子里有没有『我』」判断主语会翻车，
   得先把「帮我 / 给我 / 提醒我」这类短语抹掉再判。
9. **工具循环里追加的 messages 是闸门拼出来的副本**，别往 `self._turns` 里塞
   tool 消息：那样下一轮对话会带着一堆上次的工具结果，上下文越滚越大。
10. **收尾那次一定不能传 tools** —— 带着它可能继续调，永远说不完。
11. **资料库索引要跟着源文件清理**：`build_index` 会把「配置目录下、文件已经删了」
    的旧索引一并清掉，否则删掉的文档还会被念出来。
12. **uvicorn 一定要 `log_config=None`**：它默认会 `dictConfig` 一把，
    把 root 上的控制台/文件 handler 全换掉——机器人日志会从这一秒开始消失，
    还查不出原因。`app/panel/server.py` 里写死了。
13. **面板改参数别回写 `config.yaml`**：那份文件的注释是它的主要价值，
    PyYAML 一回写全没。改的值走 `data/override.yaml` 覆盖层，可逆。
14. **工具结果不算进闸门预算的历史问题已修**：现在每轮工具循环开头都会量一次
    上下文总量，快到窗口上限就停掉工具、逼模型直接回答（日志「上下文快满了」）。
15. **真机上会被 wechatauto 限流**：120 秒内发超过 6 次，它会强制冷却一段时间再发
    （库里的窗口是 30~75 秒，日志会写「拟人节流」和具体秒数）。这不是卡死，等一会儿就好；
    嫌频繁就调 `wechat.merge_window` 或 `wechat.max_bubbles`。
16. **`kb.dirs` / `kb.exts` 一定要写成列表**（`[knowledge]` 不是 `knowledge`）：
    写成字符串会被按字符遍历，去找 d/o/c/s 四个目录，索引永远是空的还不报错。
    代码里已经兼容了（`_as_list()`），但配置还是按列表写更清楚。
17. **面板的日志环必须登记在 `logging_setup._EXTRA` 里**：wechatauto 导入会清掉
    root 上所有 handler，直接 `addHandler` 的会被一并清走，面板日志区就空了。
18. **额外配置项别「只加开关不接线」**：`wechat.split_reply` 曾经在面板上能关，
    但 `_send()` 根本没读它——用户以为关了，其实一直按长度切。
