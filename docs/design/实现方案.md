## 零、三期总览

| | 内容 | 判断标准 |
|---|---|---|
| **V1（本次）** | 发送取证 + 长期记忆 + 语义检索 + 闸门 + 幂等 | 她能记住以前说过的事，且真能发出去 |
| **V2** | 时间衰减、容量淘汰的精细化、复习加成、反馈**只记录不生效** | 跑一周，看记忆是否被正确挑起 |
| **V3** | 每日日报、事件合并、反馈真正生效、效价与唤醒 | 你确认前面有用才做 |

**为什么这么切**：V1 解决的是「她记不住以前的事」——这是你真正的抱怨。V2/V3 解决的是「记得更聪明」——这是加分项。把加分项和核心捆在一起验收，等于用一个不可测的目标掩盖一个可测的目标。

## 一、V1 做什么

**接入**（从旧版搬，不重写）
- 沿用旧版那条已验证能收消息的通道，先把它跑到「手机真收到一条」。
- 发送加重试与失败留档。

**记忆**
- 记忆单元：原文、向量、类型（闲聊/偏好/事实/指令/待办）、是否未解决、重要度（离散档）、创建时间、最近被引用时间、被引用次数、版本状态。
- 写入前查重：只和有效记录比。低于下限新增；高于上限判为同一条并更新（旧条作废、留档、不进检索）；中间灰区问一次模型。
- 容量满了按「最久没被用 + 重要度最低」淘汰一批，**淘汰而不是降级**。

**检索**
- 向量召回（本地模型）为主，关键词兜底。
- 两项打分：语义相似度占七成、重要度占三成。
- 证据门槛：低于线的不进上下文，**不凑数**。
- 进上下文的记忆，被引用次数 +1、最近引用时间刷新。**只记事实，不动强度**。

**闸门**
- 预算：最近对话七成、记忆三成，另留固定空间给回复。
- 超限先砍记忆条数，再砍单条长度，**最近两轮永不砍**。
- 所有记忆都得过这道闸。

**编排**
- 自己发的消息丢弃；同一会话串行，不同会话并行；已处理的消息标识持久化，重复的直接跳过。

## 二、V1 明确不做

| 不做 | 为什么 |
|---|---|
| 时间衰减曲线 | 第一版没有强度数值可衰减，先用「重要度 + 被用次数」排序，够用且没有调参空间 |
| 四级降级（原文→摘要→关键词→骨架） | 每次降级要调模型写摘要，400 条的库不需要。V1 用淘汰代替，简单可解释 |
| 时序边、事件合并 | 只服务日报叙事，V1 没有日报 |
| 效价、唤醒度两个连续值 | 精度用不上，V1 只留「是否未解决」一个情绪相关的标记 |
| 反馈闭环（接不接话茬） | 误判风险高，等你先看 V1 的实际检索质量再决定 |
| 每日日报 | 与记忆系统是两个产品，不该捆在一起验收 |
| 向量数据库、消息队列、插件框架 | 400 条走内存暴力算，比什么都快 |

## 三、V1 的六项口径

| # | 口径 | 理由 |
|---|---|---|
| 1 | 向量用**本地小模型**（已实测：查「咖啡」命中「爱喝美式」0.654） | 不注册、不走外网、80 MB、单次 0.01 秒 |
| 2 | 记忆**常驻内存 + 追加日志 + 定期快照**，不用数据库 | 主文档已定「内存加文件」 |
| 3 | 容量 **400 条**，满了淘汰最没用的 | 淘汰比降级简单，且不会出现「只剩关键词还占着位」的中间态 |
| 4 | 投递**至少一次 + 幂等去重** | 宁可重复被去重，不可漏；旧版漏过消息 |
| 5 | 发送失败重试两次（2 秒、5 秒）后留档放弃，同内容 60 秒内不重发 | 无限重试刷屏比发不出去更糟 |
| 6 | 检索**两项打分**（相似度 0.7 + 重要度 0.3） | 四项权重是第一版最大的调参陷阱 |

## 四、V1 模块（七个都在，只是有几个是空壳）

| 模块 | V1 里的样子 |
|---|---|
| 输入监听 | 完整。白名单、丢自己、按会话串行、断线退避重连 |
| 打标 | 半量。只出「类型」和「是否未解决」；纯规则，不调模型 |
| 记忆存储 | 完整。查重、版本作废、追加日志、容量淘汰 |
| 检索 | 完整。召回、两项打分、门槛、引用计数 |
| 闸门 | 完整。预算、回砍、唯一入口 |
| 输出 | 完整。切分、限速、重试、失败留档 |
| 日志整理 | **空壳**。只负责「定时记一行统计」，不生成日报 |

空壳的意思不是删掉，是**留好位置和契约**，V3 往里填，核心流程一行不改——这正是主文档的扩展判据。

## 五、失败矩阵（V1 必须覆盖的七种）

| 坏了什么 | 兜底 | 你能看到什么 |
|---|---|---|
| 向量模型加载失败 | 退关键词召回 | 日志一行提示，功能降级不停摆 |
| 模型超时/限流 | 换短上下文重试一次，仍失败回一句说明 | 微信里一句「有点卡」，不是报错 |
| 发送失败 | 重试两次，留档 | 日志里有「未送达」和原文，能手工补发 |
| 微信断连 | 退避重连（1 秒起翻倍，上限 30 秒） | 窗口里醒目提示，不静默 |
| 记忆文件写失败 | 拒绝写入并上报，不假装成功 | 明确失败，不丢数据 |
| 日志某行损坏 | 跳过该行继续回放，计数上报 | 启动时一行「跳过了几条」 |
| 第二个实例启动 | 直接提示已有实例，不抢文件 | 不会再出现多开抢着回复 |

## 六、V1 验收（只看现象）

1. **发送**：你手机收到机器人发的一条测试消息。
2. **记得住**：先聊「我喜欢喝美式，不加糖」，隔十轮后问「推荐个咖啡」，她能顺着美式说。
3. **捞得到**：库里存「上周跟老张约了周三看球」，问「我和老张约了啥」，能答出周三看球。
4. **不凑数**：问一件库里完全没有的事，检索为空，她不该硬编。
5. **不重复**：同一条消息投递两次，只回一次。
6. **发得出长度**：长回复自动拆条，条与条之间有间隔。
7. **不崩**：拔掉网络、关掉微信、塞 50 轮历史，各试一次，都不报错。
8. **对照清单**：从你的聊天里挑 20 条「她本该记得却没记住」的事，V1 前后各测一次，捞回几条一目了然。

第 8 条是唯一能证明「这次优化到底值不值」的东西。**前面七条只能证明「没坏」，只有这一条能证明「变好」。**

---

## 七、实施顺序

1. **搬接入层**：只搬旧版的微信收发，不改逻辑，跑到手机收到一条。
2. **管线空转**：七个模块用假消息串起来，不接模型不接微信，证明闸门在、日志有。
3. **记忆与检索**：最有价值的一块，配演示（存美式、问咖啡）。
4. **闸门与输出**：预算、回砍、切分、重试。
5. **接真实微信**：关掉假输入，观察一天。

每一步都有独立演示，演示附运行方式和预期现象，**你亲手跑出来才算过**。

---

## 八、需要你点头的四处

1. **容量 400 条 + 淘汰制**（不做降级）—— 这偏离了主文档的降级设计，属于我改你的规则。
2. **打标只保留类型和未解决**，去掉效价与唤醒 —— 同样是砍你文档里的东西。
3. **检索两项打分**，四合一留到 V3。
4. **第 8 条验收的 20 条对照清单谁来出** —— 你给，还是授权我去翻聊天记录自己挑。
