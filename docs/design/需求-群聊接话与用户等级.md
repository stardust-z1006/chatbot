# 需求：群聊接话判定升级 + 用户等级体系

> 本文是**可直接执行的规格**，不是设想。所有阈值、权重、字段名、函数签名、验收命令都在这里定死；
> 实施时不需要再做设计决策，只需按 §7 的阶段顺序落地并跑 §8 的验收。
>
> 代码基线：2026-10-26 20:04 之后的版本（`_chat_lock` / `MemoryStore` 加锁 / touch 精简行已就位）。
> 文中行号以该基线为准。

---

## 1. 目标

**一句话**：把「群里必须 @ 才理」换成「第一句被叫到、之后能接着聊」，并让特定账号在触发、上下文、记忆、人设四个维度上获得可感知的更高待遇。

两条主线，各自有独立验收：

| 主线 | 要解决的问题 | 验收口径 |
|---|---|---|
| A. 接话判定 | @ 了不理／不 @ 不理／别人聊天时乱插嘴 | 造 40 条群聊样本，`@我` 100% 回、`@别人` 100% 不回、熟人称呼 ≥90% 回、陌生人纯疑问 0% 回 |
| B. 用户等级 | 「我是谁」无法表达，机器人对所有人一视同仁 | 把某 wxid 设为 owner 后，仅他享有：更低接话阈值、更多上下文轮数、群内可写入记忆、索引更多记忆、人设里带称呼 |

**不追求**：让机器人在群里像人一样自然参与讨论。V1 的定位是「被叫到会说、熟人能接两轮」，插嘴代价高于漏回代价。

## 2. 现状与已核实事实

### 2.1 判定链现状（`app/bot.py:623-629`）

```python
def _passes_filter(self, chat_id, text, mode="auto") -> bool:
    if mode != "at":
        return True
    at_me = bool(self.me) and ("@" + self.me) in text
    keywords = [str(k).lower() for k in (self.cfg.get("wechat.group_keywords") or [])]
    return at_me or any(k in text.lower() for k in keywords)
```

三个实证缺陷：

| # | 缺陷 | 证据 | 后果 |
|---|---|---|---|
| 1 | `@` 精确子串匹配 | `bot.py:627` 用 `"@" + self.me`；`_strip_at`（`bot.py:639`）用了 `\s*` 却没回馈给判定 | 群昵称 ≠ 账号昵称时永不命中；微信 4.x 在 `@` 与昵称之间插 U+2005，也失配 |
| 2 | 关键词是子串匹配 | `bot.py:629` `any(k in text.lower())` | 配 `deep` 命中 `DeepSeek`；配 `深` 命中「深度学习」 |
| 3 | 无对话状态 | 每条消息独立判定；唯一的定时器是 `merge_window`（`bot.py:273`） | 被叫到一次之后，下一句就「不认识」了 —— 「接话」缺的正是这个 |

补充事实（已核实）：`wechatauto.WeChatDB` 的源码里 `at_list` / `atuser` / `at_user` 均 0 命中，**拿不到结构化 at 列表**，只能文本判定。

### 2.2 等级相关现状

- 会话策略（`app/chats.py:106-113`）是 **chat_id 维度**：`mode_for` / `persona_for` / `allow_sender`。一个人出现在 10 个群里就是 10 份独立配置。
- 群聊完全不读写记忆：`bot.py:365` `is_group`、`bot.py:369` `hits = [] if is_group`、`bot.py:372` `if not is_group and worth_remembering(...)`。原因写在注释里（隐私 + 400 名额被闲聊占光），是对的。
- `TurnContext`（`app/tools/__init__.py:30-35`）只有 `chat_id/chat_name/is_group/pending_voice`，没有「谁在说话」。
- `_trim_turns`（`bot.py:645-648`）固定 `MAX_TURNS=12`，不分人。
- 检索（`app/retrieve.py:46`）`min_score` 是实例属性，不能按次覆盖。

### 2.3 必须顺手修的既有缺陷

**合并窗口按 `chat_id` 合并**（`bot.py:266-277`）：群里 A 说「今天开会」，B 说「几点」，两条会被拼成一句 `query`，而 `_flush` 用的是**最后一条** msg 的 `chat_name`。等级与连续性都以「谁在说」为前提，这个必须先按 sender 拆开，否则 A 的等级会算到 B 头上。

## 4. 数据模型

### 4.1 `data/people.json`（唯一来源）

```json
{
  "updated": 1793102400.0,
  "people": {
    "wxid_eneq2rru9kk612": {"level": "owner", "alias": "老板", "note": "本人", "updated": 1793102400.0},
    "wxid_abc123":         {"level": "friend", "alias": "老张", "note": "", "updated": 1793102000.0}
  }
}
```

- 键是 **wxid**，不是昵称（昵称会改、会重名）。
- **必须独立成文件**：不进 `chats.json`（那是 chat 维度，一个人会出现在多个群，等级会被复制成多份）；不进记忆库（会被容量淘汰、被语义检索、被模型 `remember` 改写 —— 而等级是权限边界）。

### 4.2 四级

| level | 中文 | 接话阈值 | 上下文轮数 | 群内写记忆 | 群内检索 | 人设注入 |
|---|---|---|---|---|---|---|
| `owner` | 主人 | 45 | 16 | ✅ `scope=group` | ✅ top_k 8 / 门槛 0.45 | 「你的主人，你叫他〈alias〉」 |
| `friend` | 熟人 | 60 | 12 | ✅ `scope=group` | ✅ 默认 6 / 0.55 | 「你认识的人，你叫他〈alias〉」 |
| `stranger` | 陌生人（默认） | 999（等于只能被叫到） | 8 | ❌ | ✅ 默认 | 无 |
| `blocked` | 不理 | — | — | ❌ | — | — |

`999` 是刻意的：陌生人只认「被叫到」（`@` 或称呼），不参与主动接话。

### 4.3 记忆 scope

`Memory` 新增字段 **追加在 dataclass 末尾**（`app/memory.py:53` 之后）：

```python
scope: str = "private"   # private=私聊 / group=群内
```

旧记录没有这个键，`Memory(**item)` 走默认值 `private` —— 现有 24 条全部落为私聊记忆，无需迁移脚本。

检索范围是硬边界：

| 场景 | 检索 scope |
|---|---|
| 私聊 | `("private",)` |
| 群聊 | `("group",)` |

群聊**永不召回**私聊记忆。这是 §2.2 里隐私红线的具体实现方式，不是可配置项。

## 5. 设计决定（每条含理由与取舍）

**D1　`at` 模式语义升级，不新增模式。**
`at` 从「@ 或关键词命中」变成「打分 ≥ 阈值」。`auto` 保持「一律回」。想用打分就把群设为 `at`（也是 `group_at_only=true` 的默认）。

**D2　@ 识别两段式：候选名精确匹配 + 成员表排除法。**
候选名 = {账号昵称 `self.me`、角色名、`people.alias`、`config.people.self_names`、本群成员表里自己那条的 `nick_name`/`remark`}。
- 命中任一 → `+100`（确定是我）。
- 未命中，且 `@` 后的名字**不在本群成员表**里 → `+60`（置信度中：群里 @ 了一个陌生人，多半是在 @ 机器人）。
- 命中成员表里的别人 → `-50`。
- 成员表读取失败或为空 → **排除法不启用**，只认精确匹配（保守）。

理由：`get_group_members` 只返回账号昵称与备注，**拿不到群内昵称**（已核实其 SQL 只 join `contact`），所以「@ 了我」在群昵称被改过时无法直接判定，只能靠排除法兜。取舍：宁可少数情况漏判（不回），不可误判成「@ 我就回」在群里插嘴。

**D3　称呼匹配分两套规则。**
- ASCII 词（`deep` / `deepChat` / `bot`）：前后不能紧邻字母数字 —— `(?<![a-z0-9])deep(?![a-z0-9])`，大小写不敏感。`DeepSeek`、`deepbot` 不命中。
- 中文词：必须处于「呼语位置」= 文本前 8 个字符内，或紧跟 `，,：: 、 空格` 之后，或紧跟 `@`。这样「小深，在吗」命中，「深度学习是什么」不命中。

理由：中文短名做词边界会误杀（「小深你好」里「深」后面是「你」），做纯子串又会误触发。呼语位置是中文里「叫名字」的实际形态。

**D4　连续性窗口：第一句必须被叫到，之后靠窗口。**
我在群里回复成功后，为 `(chat_id, sender)` 开 90 秒窗口；窗口内**这个人**继续说 `+40`。同一个人连说 3 轮后窗口延到 180 秒。别人说话不享受这 40 分。一小时无活动清理，容量 256 条。

理由：这是「减少必须 @」的主力且实现最轻。取舍：**冷启动不接话** —— 陌生对话第一句必须被叫到，避免机器人在别人的讨论里突然插嘴（插错一句的代价远大于少回一句）。

**D5　只在发送成功后开窗。**
开窗点必须在 `_flush_body` 里 `_send` 返回成功之后（`bot.py:326`）。发送失败还开窗，会导致「我以为在跟你聊，其实你没收到」。

**D6　阈值拆成两档：被叫到 / 主动接话。**

```
if level == blocked: 不回
if not is_group: 回（私聊不受本机制管）
if not engage.enabled: 走 legacy（原 _passes_filter）
if score >= call_score(50): 回                 # 被叫到：@ 或称呼
if level in (owner, friend) and score >= join[level]: 回   # 主动接话
否则不回
```

`call_score=50` 保证「叫名字照旧能叫应」，与现状 `group_keywords` 行为一致，不产生回归。

**D7　群内记忆按等级 + 配额。**
只有 owner/friend 的群消息可写 `scope=group`；`memory.group_quota`（默认 80）限制群记忆条数，`_evict` 先按配额淘汰超额 group，再按总容量淘汰。理由：原来「一刀切禁止」是为了防名额被占光，配额能精确解决同一问题而不牺牲功能。

**D8　配置项只暴露能调出差别的那几个。**
权重（100/60/50/40/30/-50/-30）写死在 `engage.py` 常量里，不进面板 —— 七个权重就是七个调参黑洞，且业务上没人能凭直觉调。面板只给：开关、`call_score`、`join_owner`、`join_friend`、`continuity_window`。

**D9　`people.owners` 是种子，不是第二来源。**
`PeopleStore.level_of()` 的判定顺序：`people.json` 有记录 → 用记录；无记录但命中 `config.people.owners` → `owner`；否则 `default_level`。一旦面板给该 wxid 建了记录，config 就彻底不再参与 —— 保证「改一处、只有一处生效」。

### 6.1 `app/people.py`（新，约 140 行）

```python
LEVELS = ("owner", "friend", "stranger", "blocked")

    def get(self, wxid: str) -> Dict[str, Any]    # {level, alias, note, updated, seeded}
```

```python
class Verdict:
    hit: bool

              persona_names: Sequence[str], now: Optional[float] = None) -> Verdict
```

`judge` 的实现顺序（**顺序即语义**）：

1. `level = people.level_of(sender)`；`blocked` → `Verdict(False, 0, level, ["blocked"])`。
2. 非群 → `Verdict(True, 0, level, ["private"])`。
3. `engage.enabled` 为假 → 返回 `hit=None` 的 legacy 标记（由 `Bot` 走老逻辑）。
4. 归一化文本，算六项信号，累加得分。
5. 按 D6 出 `hit`。
6. 记 `state.engage(hit, reasons)`。

**不持锁、不调网络、不读磁盘**（`MemberCache` 首次读库除外，有 TTL）。

```
POST /api/people            → body {wxid, level?, alias?, note?} → {ok, item}

GET  /api/status            → 追加 engage:{hit,skip,by_reason}, people:{count,owners}
```

`items` 的合并来源：`people.json` 全部 + `bot.bridge.sessions()` 里的私聊会话（`is_group=False`）+ 自己（`bot.bridge.self_wxid`，标 `is_self=true`）。按 wxid 去重，`people.json` 优先。无 bridge（web 模式）时只出 `people.json` 与 `config.people.owners`。

`level` 非法 → `schema.FieldError` → 400。落盘失败 → 500（复用现有 `_save_failed`）。

### 6.7 `app/memory.py` / `app/retrieve.py` 改动点

```python
# memory.py
scope: str = "private"                       # Memory 末尾新增
def put(self, text, tags=None, scope="private") -> Dict[str, Any]
def active(self, scope: Optional[str] = None) -> List[Memory]        # None = 全部
def active_scopes(self, scopes: Sequence[str]) -> List[Memory]
def _evict(self)                                              # 先 group 配额，再总容量

# retrieve.py
def search(self, query, top_k=None, mark_used=False,
           scopes: Optional[Sequence[str]] = None,
           min_score: Optional[float] = None) -> List[Hit]
```

`_best_match` 的查重范围**不按 scope 过滤**（跨 scope 查重，避免「同一句话在群里说一遍又私聊说一遍」存成两条）—— 这条要在代码注释里写明，否则后人会以为漏了过滤。

`_evict` 的两段式：

```
while len(active("group")) > group_quota:  淘汰最弱的 group
while len(active()) > capacity:            淘汰最弱的（不分 scope）
```

第二段不区分 scope 是刻意的：极端情况下先保证总量不超，而不是让两条规则打架。

## 9. 风险与回退

| 风险 | 触发条件 | 处置 |
|---|---|---|
| 误插嘴 | 成员表缺失 → 排除法把「@别人」判成「@我」 | 排除法只在成员表非空时启用；`+60` 只够过 `call_score`，够不到主动接话；日志可回查 |
| 第一句永远不接 | 用户以为「升级后不用说 @ 了」 | 文档与面板 hint 明确写：**第一句要被叫到，之后才靠连续性** |
| 群记忆挤占私聊名额 | 群聊活跃 | `group_quota=80` 两段式淘汰；面板可调 0 关闭 |
| 判定变慢 | 每群消息一次成员表读库 | TTL 600 秒 + 容量 64；其余全内存 |
| 老记忆不兼容 | 无 `scope` 字段 | dataclass 默认值兜住，S2 验证门第 6 项 |
| 行为整体跑偏 | 权重不适合实际群 | 面板一键 `group.engage.enabled=false` → 完全退回现状判定（legacy 分支保留） |

**回退**：`engage.enabled=false` 是软回退；硬回退覆盖 `_回退-20261026-2004/` 里的 `app/`、`tests/`。

## 10. 必须处理的边界条件清单

实施时逐条打勾，漏一条视为未完成：

1. `self.me` 为空（账号没读到）→ 不能因此把所有群消息判成「不是我」。
2. `sender` 为空（`_adapt` 里 `sender_username` 缺失）→ 等级退回 `default`，不崩。
3. `chat_id` 为空 → 已在 `on_message:240` 拦掉，改动后保持。
4. 成员表里同一昵称对应多人 → 只取第一个，且**该名字不参与**「@ 别人」判定（歧义按「不是我」处理？不：歧义按「不确定」处理，不给分也不扣分）。
5. 文本全是 @ 没有正文 → `strip_mentions` 抹空后返回原文，交给「太短」扣分。
6. `alias` 为空 → 身份句用「他」，不出现「你叫他「」」。
7. `people.json` 损坏 → 按空库启动 + warning（对齐 `chats.py:68-70`）。
8. `people.json` 写入失败 → 面板 500，内存状态不前进（先落盘再承认，对齐 `MemoryStore._append` 的新语义）。
9. 群成员表返回 >500 人 → 只用前 500 个建索引，避免判定时线性扫描过慢。
10. `engage.enabled` 热改（false→true / true→false）→ 必须立刻生效（`apply_config` 重建 `Engager`）。
11. `memory.group_quota` 调小 → 立刻按新配额收一遍（`apply_config` 里 `enforce_capacity()`）。
12. `blocked` 的人不进 `_pending`、不写 `seen`、不写记忆 —— 与 `off` 模式同等待遇。
